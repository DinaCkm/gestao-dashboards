# Regras de Segurança — gestao-dashboards

## Regra 1: Nunca fazer push após rebase sem revisar o diff completo

**Contexto do erro (28/04/2026):**
Ao tentar fazer `git push` de uma mudança pequena (campo de vídeo no formulário de cases), o GitHub rejeitou porque havia commits novos no remote. Foi executado `git pull --rebase origin main` para sincronizar. O rebase incorporou silenciosamente commits do Codex/DinaCkm que continham um bug latente no endpoint `meuDashboard` (usava `getAlunos()` em vez de `getAlunoFromCtx`). O push foi feito sem revisar o diff, e o bug foi para produção, quebrando o Portal do Aluno e a Performance para todos os alunos.

**Protocolo obrigatório antes de qualquer push após rebase:**

1. Executar `git log --oneline origin/main..HEAD` para listar todos os commits que serão enviados
2. Para cada commit que **não foi escrito por mim**, executar `git show <hash> --stat` e revisar o diff
3. Verificar especificamente alterações em `server/routers.ts` e `server/db.ts` — qualquer mudança em endpoints críticos (`meuDashboard`, `meuPerfil`, `performance`) deve ser testada antes do push
4. Se houver dúvida sobre algum commit externo, **não fazer push** e informar a usuária para revisão

**Regra resumida:** `git pull --rebase` + `git push` sem revisão = PROIBIDO neste repositório.
